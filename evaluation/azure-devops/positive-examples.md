# Azure DevOps – Positive Beispiele / S4-Beobachtungen

Bezug: `docs/RESEARCH_GUIDELINES.md` Abschnitt 8 (S4), Abschnitt 9 („Positive Beispiele müssen ebenso dokumentiert werden wie Barrieren“); `docs/DECISIONS.md` D-009.

S4 ist **kein Fehler** und keine niedrige Fehlerschwere, sondern eine Beobachtung oder ein positives Beispiel: ein korrektes, erwartbares oder kontextabhängiges Interaktionsmuster. Beispiele: korrektes `tablist`-Pattern, funktionierende Pfeiltastennavigation in einem Composite Widget, verständliche Combobox-Ansage.

## Eintragsvorlage

```
### <ID, z. B. AZ-POS-001>

- Plattform: Azure DevOps
- Workflow: Work Items/Boards | Pull Requests
- Testmethode: Keyboard-only | NVDA | DOM-/ARIA-Analyse
- Datum: nicht erhoben
- Beobachtung: nicht erhoben
- Warum kein Fehler / warum positiv: nicht erhoben
- Bezug zu ARIA-Pattern (falls zutreffend): nicht erhoben
- Screenshot-/Video-Referenz: nicht erhoben (Ablage gemäß evidence/README.md)
```

## Einträge

Noch keine Beobachtungen. Dieser Abschnitt wird erst nach tatsächlicher Testdurchführung befüllt.
